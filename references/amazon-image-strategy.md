# Amazon 图片前置策略

把消费者需要知道什么，落实为每张图可执行、可核对的任务。输入是用户为当前任务提供的产品资料、素材和可选市场资料；不要求特定资料目录、知识库或额外技能。策略负责购买理由、事实、内容分工及画面如何说明答案，随后由 ecom-image2 选择视觉表现、组装提示词、生成和检查。

## 何时使用

- 本模块默认平台为 Amazon；仍需明确影响内容的站点、语言、产品版本和任务用途。其他平台由 ecom-image2 原有流程处理。
- Amazon 新做图片、整套重做、重新分配卖点或信息顺序时使用。覆盖白底首图、Listing 附图、普通 A+ 和高级 A+；主图组指首图与附图。
- 已有策略先核对产品、品牌、站点、规格、包装及当前事实，适用则复用。纯局部修图只补受影响的问题、事实与保留项，不重做全套研究。
- 只要求策略时交付文字策略并结束，不调用生图接口。已要求生图且事实、方向和素材明确时，展示策略后继续制作，不额外增加一次策略审批；仅澄清影响执行的实质缺口。

## 1. 整理本品资料和素材

优先使用当前任务中已有且适用于所选版本的资料，缺什么补什么，不要求用户填一整套固定档案。

| 输入 | 核对内容 |
|---|---|
| 本品事实 | 品牌、产品版本、尺寸、材质、功能、包装包含物、正确用法及限制；每项保留说明书、参数表或用户确认等出处 |
| 本品素材 | 实拍、包装、结构和细节图；标注对应版本、可见结构与必须保留的外观 |
| 现有内容（可选） | 当前 Listing、已有主图组/A+、品牌规范、关键词或目标人群；核对适用范围及已经讲过的内容 |
| 市场资料（可选） | 评论、问答、竞品图片或分析报告；保留来源和日期，不能作为本品参数依据 |
| 本次交付 | 图片用途、数量、站点、语言、端型、模块及尺寸要求；文件输出位置遵循用户或当前项目约定 |

形成可用事实、素材与缺口清单。冲突资料先确认适用版本和较新的本品依据；竞品报告中的旧待补状态不能覆盖新的本品确认。未确认的事实不进入文案或生成画面。

制作前实际查看所用本品图片，记录参考角色与保留项。仅有用户描述时可以策划，但注明原图尚未查看；历史成图可用于风格和已展示内容对照，不能替代本品事实或自动成为全套构图母版。参考图看不清的背面、内部或功能不得补造。

## 2. 整理消费者问题与依据

有可用评论或问答时，提取购买动机、被认可的利益、疑问、使用困难、尺寸/包装误解和预期落差。竞品资料可帮助发现问题，但本品是否能回答，必须回到本品事实。

记录：**消费者问题｜来源与定位｜证据类型及样本支持｜购买影响｜本品答案及依据｜适合用图解决吗**。

- 保留适用的 ASIN、站点、日期及评论 ID、问答位置或文件段落。只有原文可去重、分母可说明时才统计频次；同一评论在同主题中不重复计数，报告与其原文不算两份证据。
- 有报告无原文时标“报告结论，原文未回查”，频次写“不可统计”；只有竞品图时标“竞品表达观察”。两者均不能写成已核实的高频消费者需求。
- 没有市场资料时，依据本品事实形成基础购买问题，标“策划判断”，继续有依据的策略。不编造评论、频次或普遍需求，也不自动开始外部采集。
- 区分产品缺陷、表达不清和使用错误。产品缺陷属于产品侧问题，不能靠图片承诺消除；正确用法必须来自本品说明或确认。
- 有竞品视觉资料时简述“共同表达、尚未讲清的问题、本品可提供的解释与依据”；没有则注明未作视觉对照。表达更清楚不等于性能更强，不能为差异化发明优势。

## 3. 安排图片任务和顺序

先明确目标人群、情境、期望结果、主要购买障碍及本品支持依据，形成一个核心购买理由。按购买/误购影响、证据及本品可回答程度安排顺序：适配或使用条件决定能否使用时优先解释，否则按价值理解、操作门槛或体验需求安排。

一张图回答一个主要问题，可以包含直接支持它的细节。写清买家看完应理解的结论，以及可见动作、真实结构、使用关系或尺度如何说明它；不能只填“居中、左右布局、三个图标”等版式名称。

| 用途 | 信息职责 |
|---|---|
| 白底首图 | 看清实际商品、款式与包含物；按适用的首图要求执行，不能套用附图叠字或分块设计 |
| Listing 附图 | 帮助快速判断购买价值与是否适用；依据本次障碍选择利益、尺寸、适配、细节、用法或场景 |
| 普通 A+ | 用所选模块补足使用解释、产品细节、条件和选择依据，与附图协同 |
| 高级 A+ | 先确定整页理解与模块承接，再选择当前可用模块；不把附图简单改成宽图 |

联合规划本次范围内的主图组与 A+。只做 A+ 时参考可用的现有主图组，不扩大为重做 Listing；没有可用图组时标“未对照”，不编造已经展示的内容。

每个 A+ 模块注明**关联图片、已讲内容、本模块新增帮助或必要承接**。核心利益可以呼应，开场或转场可以帮助独立理解；仅换尺寸、改标题或重复参数不算新增解释。没有内容贡献时合并、换题或提出数量调整，不用重复卖点凑数。

- 用户指定数量优先；未指定时根据有效问题和已选模块提出合理数量并说明。数量是策划建议，不是平台统一规定。分别记录 A+ 模块数与素材图片数。
- A+ 模块和尺寸来自本次选用的模块规格，不沿用固定“7 模块”或将所有 A+ 视为同一尺寸。尚未选定模块可先策划，执行前补齐。
- 普通/高级 A+ 都可只交付静态图片。采用原生交互模块时区分图片、原生文本和配置，不把画出的按钮当成已实现交互。
- 需要 PC/移动端时，两端使用相同问题和事实，分别构图和压缩文案，不硬裁另一端成图。
- 文案具体简短，普通描述不一概要求测试报告；量化性能、认证、效果和明确比较需要对应本品证据。场景只能说明用途，不能代替性能证明。

## 4. 交接制作与检查

用 [策略记录模板](amazon-image-strategy-template.md) 维护一份当前记录；已有记录则补充本次相关字段，单张任务只填写相关行。只读任务可直接在聊天输出，写文件时使用用户或项目指定的输出目录。无指定目录时先确认保存位置。

交接包括核心购买理由、逐图任务表、资料缺口、暂缓项、产品版本/站点/端型及素材角色。向用户说明策略后：只做策略则结束；继续生图则回到 `SKILL.md` Step 2，不重新调用本模块。

- 按每张图的任务选择场景模板及视觉参考，保留现有 Campaign Style Lock、prompt 组装、生成通道和技术检查。共享品牌字体、色彩关系与制作质感；角度、镜头、主体占比和构图按本图任务选择，同一商品颜色变体等明确要求同构图的任务仍保持一致。
- Amazon 策略中的问题、数量和顺序优先于 `funnel-set.md` 的通用槽位、排序和 A+ 映射；模板中的例子、默认文案、认证和对比都不能变成本品事实。策略不覆盖实际平台要求。
- A+ 制作时区分 `delivery_size`（模块交付像素）和 `generation_size`（符合生成入口限制的尺寸）。记录规格出处、内容安全区域及裁切/等比导出方案；生成后检查实际交付像素与可读性。模块尺寸不能直接假定为合法的 API 生成参数，尺寸或导出方案未定时不能宣称素材可上传。
- 除视觉和技术检查，逐图确认画面是否说明原定答案、事实是否正确；A+ 对照相关主图组检查新增帮助或必要承接。未取得相关图组时标“未对照”，发现问题只修正受影响的策略行和图片。
- 交付实际完成的策略、图片或提示词包及对应检查结果。策略完成、生成完成、技术检查和平台接受分别说明；保存和后续更新遵循本次约定，不自动写回外部资料。
